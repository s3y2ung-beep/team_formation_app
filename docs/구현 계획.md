## 파일 구조

```
team_formation_app/
├─ streamlit_app.py          # 화면(로그인, 학생 화면, 관리자 화면)
├─ teamapp/
│  ├─ config.py              # 비밀 값 읽기(.env 또는 Streamlit Secrets)
│  ├─ db.py                  # DB 연결 풀, 질의
│  ├─ rules.py               # 팀 규칙 검사(순수 파이썬)
│  ├─ roster.py              # 명단 CSV 읽기와 검사
│  ├─ service.py             # 지원, 투표, 마감, 확정(트랜잭션)
│  ├─ solver.py              # 모든 경우를 따지는 배정 찾기와 불가능 이유
│  └─ ai.py                  # 오픈라우터 호출, 120초 제한, 배정안 검사
├─ schema.sql                # tf_ 테이블을 만드는 SQL
├─ scripts/keepalive.py      # 매일 DB에 질의(깃허브 Actions가 실행)
├─ .github/workflows/keepalive.yml
├─ tests/                    # 자동 시험(pytest)
├─ samples/                  # 연습용 시나리오 명단 CSV 3개
├─ docs/PRD.md, docs/구현 계획.md
├─ requirements.txt, .env.example, .gitignore
└─ README.md                 # 공고 7.1절 양식의 보고서
```

## 1단계: 뼈대와 로그인

- 만들 것
  - `schema.sql`과 이를 DB에 적용하는 코드
  - `config.py`: 비밀 값을 읽고, 있는지 여부만 알려 주는 함수
  - `db.py`: 연결 풀을 한 번만 만들고 다시 씀. 꺼낼 때 끊긴 연결을 확인함
  - 앱이 시작할 때 `ADMIN_PASSWORD`로 관리자 계정을 만들거나 갱신
  - 로그인, 로그아웃 화면(`login_student_no`, `login_password`, `login_submit`, `whoami`, `result`)
- 완료 기준
  - 관리자로 로그인하면 관리자 화면이 보임
  - 틀린 비밀번호, 없는 학번은 "막힘"으로 시작하는 안내가 나오고 로그인되지 않음
  - DB의 `password_hash` 열에 원래 비밀번호가 아닌 bcrypt 해시가 있음
- 확인 방법: 자동 시험(Streamlit `AppTest`)과 브라우저 직접 확인
- 커밋: `1단계: 뼈대와 로그인`

## 2단계: 규칙 검사 모듈

- 만들 것
  - `rules.py`: 지원 검사(막힘 이유 6개), 투표 처리, 승인 직전 검사, 필수 포함 역할 자리 계산, 확정 구성 검사 다섯 가지
  - `tests/test_rules.py`: 연습용 시나리오 3개의 단계를 DB 없이 그대로 따라가며 기대 결과를 확인
- 완료 기준
  - 연습용 시나리오 3개의 모든 단계에서 결과의 첫 단어가 기대 결과와 같음
  - 2.3절 예시 두 개(기획자;웹 프로그래머 혼자인 팀, 테스터와 발표자 팀에 보고서 작성자 지원)를 시험으로 확인
- 확인 방법: `pytest`
- 커밋: `2단계: 규칙 검사 모듈과 시나리오 시험`

## 3단계: 명단 올리기, 지원, 투표, 자동 갱신

- 만들 것
  - `roster.py`: BOM이 있는 UTF-8 CSV 읽기, 열과 역할 검사
  - `service.py`: 처음 상태 만들기, 지원, 투표. 팀 행을 잠그는 트랜잭션 안에서 규칙 검사 후 기록
  - 학생 화면: 팀 목록(`team_N`), 지원 단추(`apply_N`), 찬성과 거부 단추(`vote_yes_학번`, `vote_no_학번`), 내 투표 표시
  - 학생 화면의 팀 목록과 지원, 투표 영역을 `st.fragment(run_every=3)`로 감쌈
  - 관리자 화면: 명단 올리기(`admin_roster_file`, `admin_team_count`, `admin_start`)
- 완료 기준
  - 학생 여러 명이 서로 다른 브라우저에서 지원하고 투표하면, 다른 학생 화면에 3초 안에 나타남
  - 쉬움 시나리오 1~5단계의 결과가 기대 결과와 같음(실제 DB와 `AppTest`로 확인)
  - 같은 자리에 두 명을 넣으려 하면 DB 유일성 제약이 막음
- 확인 방법: `AppTest`로 학생마다 세션을 따로 열어 시나리오 단계를 실행
- 커밋: `3단계: 명단, 지원, 투표, 자동 갱신`

## 4단계: 마감, AI 배정, 확정

- 만들 것
  - 모집 마감(`admin_close`), 팀이 없는 학생 표시(`unassigned`)
  - `solver.py`: 모든 경우를 따지는 배정 찾기, 배정이 없을 때의 이유 만들기
  - `ai.py`: 1차, 2차, 3차 모델 차례로 호출. 모델마다 전체 120초 제한. 빈 응답, 오류, 검사 불통과를 실패로 처리
  - AI 대기 안내(`assign_status`): 몇 차 모델, 모델 이름, 경과 초
  - 3차까지 실패하면 `solver.py`로 배정. 배정안을 낸 곳을 함께 보여 줌
  - 확정(`admin_confirm`): 저장 직전에 다섯 가지 검사를 다시 함
  - `tf_ai_logs`에 모델마다 시도 결과를 남김
- 완료 기준
  - 연습용 시나리오 3개를 끝까지 해서 확정한 팀 구성이 규칙을 모두 지킴
  - 키를 틀리게 둔 상태에서도 3차까지 실패한 뒤 앱이 스스로 배정함
  - 규칙을 지키는 배정이 없는 상태를 만들면 AI를 부르지 않고 이유를 보여 줌
  - AI 응답이 120초를 넘으면 끊고 다음 모델로 넘어감(가짜 느린 응답으로 시험)
- 확인 방법: `pytest`(가짜 AI 응답), `AppTest`, 실제 오픈라우터 호출 몇 번
- 커밋: `4단계: 마감, AI 배정, 확정`

## 5단계: 배포와 DB 일시정지 막기

- 만들 것
  - `requirements.txt`, `.env.example`
  - 깃허브 비공개 저장소에 올림
  - Streamlit Community Cloud 배포, Secrets 등록, 공개 범위 바꾸기
  - `scripts/keepalive.py`와 `.github/workflows/keepalive.yml`: 매일 DB에 질의. 깃허브 저장소 Secrets에 `DATABASE_URL` 등록
- 완료 기준
  - 시크릿 창에서 배포 주소를 열면 로그인 화면이 보임
  - 배포한 앱에서 쉬움 시나리오를 끝까지 해 봄
  - 깃허브 Actions의 keepalive를 손으로 한 번 실행해 성공함
- 커밋: `5단계: 배포 설정과 DB keepalive`
